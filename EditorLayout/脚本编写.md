## 1. 整体设计与职责

编辑器处理的是尚未完全探明的 FlatBuffers 文件。Lua 的作用包括组织编辑操作，以及将新研究结论接入已有读写流程。

| 层次 | 负责什么 | 主要入口 |
| --- | --- | --- |
| 物理解释 | 字段类型、表和结构体布局 | 基础 schema、`editor.format.schema` |
| 语义映射 | 字段位置、位段、研究依据 | `fields/*.json` 公共字段目录 |
| 对象层 | 把存储结构包装成部队、势力、格子等对象 | `game`、`editor.modules.objects` |
| 操作层 | 局部修改、批量处理、表单保存 | `editor.tool`、`editor.action` |
| 界面层 | 页面、控件、参数窗口 | 布局 XML、工具声明 |
| 宿主与核心 | 文档、事务、历史、二进制重建 | C# 的 BtlScriptHost 与 BtlCore |

例如“给所有部队增加经验”只需写工具。“研究发现部队多了一个 ushort 字段”通常需要物理类型声明和对象属性。“某个字段位置改了”应修订目录或对象映射，避免在每个工具中修改路径。

日常工具优先使用 `game`。格式接入模块可以使用数字路径。`editor.internal` 是内置对象库的桥接接口，普通工具通常不需要直接调用。

## 2. 安装、加载与热更新

### 2.1 推荐目录

将自己的脚本放在编辑器实际使用的布局目录旁：

```text
EditorLayout/                 自带布局、对象库、页面与字段定义
EditorLayout.user/            用户扩展
  tools/
    my_heal.lua
    research/
      packet.lua
```

`tools` 下的 `.lua` 会递归加载。只增加工具时不需要创建用户 `layout.xml`，也不需要修改自带布局。目录位置取决于启动的编辑器副本；仓库、构建输出和发布目录可能各有一份布局，编辑时要确认使用的是哪一份。

保存为 UTF-8，在编辑器“文件”菜单执行“重新加载布局”。成功后，`editor.tool` 会出现在“脚本工具”菜单。热加载失败会保留此前有效的布局，并显示错误。

### 2.2 实际加载顺序

1. 自带 `EditorLayout/layout.xml` 中的脚本，按声明顺序加载。
2. 用户 `EditorLayout.user/layout.xml` 中显式列出的脚本，按声明顺序加载。
3. 自动发现的用户脚本，按完整路径进行不区分大小写的排序。

自动发现始终包含 `tools/**/*.lua`。如果没有用户 `layout.xml`，还会加载用户 `scripts` 目录直接包含的 `.lua`，不递归；存在用户布局时，`scripts` 中的文件应显式登记。已显式登记的脚本不会被自动发现流程再加载一次。

简单扩展可用 `00_model.lua`、`10_tools.lua` 这样的文件名排序。依赖复杂时，在用户布局中明确写出顺序：

```xml
<editorLayout format="1">
  <scripts>
    <script src="scripts/research_model.lua"/>
    <script src="scripts/research_tools.lua"/>
  </scripts>
</editorLayout>
```

脚本不通过 `require` 加载。依赖由布局或上述文件顺序管理，模块共享使用 `editor.modules`。

### 2.3 加载阶段与执行阶段

| 阶段 | 可以做什么 | 不应做什么 |
| --- | --- | --- |
| 加载脚本 | 定义函数、登记工具和动作、声明 schema/codec、扩展对象 | 读取或修改当前关卡、读取会话状态 |
| 执行工具/写动作 | 读写当前文档、使用状态与剪贴板 | 再登记工具、字段或类型 |
| 执行 getter/定位器 | 读取文档、计算显示值 | 修改文档、状态或剪贴板 |

因此，不要在文件顶层写 `local first = game.units.get(0)`。应在 `run` 或动作函数中取得当前对象。顶层保存 `local units = game.units` 这样的集合入口可以使用，它不读取文档。

### 2.4 何时需要重新打开关卡

修改工具逻辑通常重新加载布局即可。修改物理类型声明后，应保存需要保留的成果，重新加载布局，再重新打开 BTL，让读取器采用新的解释。热加载不会重新解释已经打开的文档，也不会自动搬迁字段。

修改字段目录会改变后续绑定和具名操作使用的映射，但同样不会搬迁旧位置的数据。涉及物理布局变化时，必须明确区分“用新结论重新读取”和“把旧数据迁移到新位置”。

## 3. 第一个可用工具

把下面完整文件保存为 `EditorLayout.user/tools/my_heal.lua`：

```lua
editor.tool {
  id = "user.heal_selected",
  title = "恢复选中部队生命",
  target = "selected_unit",
  description = "把当前生命恢复为最大生命，保留其他属性。",
  run = function(unit)
    unit:heal()
  end,
}
```

重新加载布局，打开关卡并选中部队，运行工具。工具会自动取得选中的部队，一次运行产生一个整体编辑事务；有实际文档变化时可一步撤销。工具只修改当前工作文档，导出 BTL 仍通过编辑器保存功能完成。

要处理全部部队，把 `target` 改为 `all_units`。宿主会逐个调用同一个 `run`，全部对象共用一次事务。无需再在 `run` 内遍历所有部队。

## 4. 工具声明与参数

### 4.1 声明字段

| 字段 | 是否必填 | 说明 |
| --- | --- | --- |
| `id` | 建议填写 | 稳定标识；省略时采用标题。建议用 `作者或项目.功能` 避免冲突 |
| `title` | 是 | 菜单中显示的名称 |
| `target` | 是 | 作用范围，见下表 |
| `description` | 否 | 功能说明 |
| `params` | 否 | 连续的 1 起参数数组 |
| `confirm` | 否 | 执行前的确认文案，例如批量删除说明 |
| `run` | 是 | `function(object, params, ctx)` |

同 ID 的工具后加载者覆盖前者，动作名和定位器名也按后加载覆盖。对象扩展字段、对象方法、schema ID 和 codec ID 则不允许重复登记。选择覆盖前先确认目标标识，避免无意替换自带工具。

### 4.2 作用范围

| `target` | 传给 `run` 的对象 | 选择规则 |
| --- | --- | --- |
| `selected_unit` | 部队 | 显式部队行优先，否则按当前格子定位 |
| `all_units` | 每支部队 | 包括集合中地图外的部队 |
| `faction_units` | 指定势力的每支部队 | 使用 `params.faction` 的势力 ID |
| `selected_faction` | 势力 | 显式势力行优先，否则根据选中部队的归属查找 |
| `all_factions` | 每个势力 | 遍历势力集合 |
| `selected_cell` | 格子 | 当前有效地图格子 |
| `all_cells` | 每个格子 | 整张地图，包括标记为不可玩的格子 |
| `stage` | `game.stage` | 执行一次，适合全局或自定义集合工具 |
| `map` | `game.map` | 执行一次，适合地图整体操作 |

没有独立的 `all_events` 等范围。需要处理事件、天气或自建集合时，使用 `stage`，再自行遍历目标集合。需要整体增删某个集合时也优先采用这种方式，避免边分发边改变正在遍历的集合。

### 4.3 参数种类

每个参数可填写 `id`、`label`、`type`、`default`、`min`、`max`、`required`、`choices`。

| `type` | 传入值 | 说明 |
| --- | --- | --- |
| `integer` | 数字 | 默认类型，要求有限整数 |
| `number` | 数字 | 有限数值，允许小数 |
| `boolean` | 布尔 | 没有提供值和默认值时取 false |
| `text` | 字符串 | 必填时不能全为空白 |
| `choice` | 选项的实际值 | 必须提供非空 `choices` |
| `faction` | 数字 ID | 势力选择，ID 范围 0–65535 |
| `unit_type` | 数字 ID | 兵种选择，ID 范围 0–65535 |
| `general` | 数字 ID | 将领选择，ID 范围 0–65535 |

`required` 默认 true。可选参数未提供时可能没有对应的表项，读取为 `nil`。`min/max` 用于数值约束，实际写入还会检查目标字段的类型范围。`choice` 的值可以是字符串、布尔或有限数字，不能把数组位置当作选项值。

```lua
editor.tool {
  id = "user.faction_level",
  title = "设置指定势力经验",
  target = "faction_units",
  params = {
    {id="level", label="经验等级", type="integer", default=10, min=0, max=255},
    {id="only_with_general", label="只处理带将领的部队", type="boolean", default=false},
  },
  run = function(unit, params)
    if params.only_with_general and unit.general == nil then
      return false
    end
    unit.level = params.level
  end,
}
```

`faction_units` 会在未声明 `faction` 参数时自动加入势力选择参数。如果自行声明同名参数，应使用正确的 ID 语义。

```lua
-- 可嵌入 params 的选项参数：
{id="mode", label="处理方式", type="choice", default="add", choices={
  {label="增加", value="add"},
  {label="覆盖", value="replace"},
}}
```

`run` 返回 `false` 表示不计入处理数量，其他返回值计数。**返回 false 不会撤销已经执行的写入**，所以跳过判断应放在写入之前。全部对象都返回 false 或没有匹配对象时，分发器会报错，整个工具事务回滚。处理数量也不等于实际改变值的对象数量。

## 5. 对象、下标与空值

### 5.1 点与冒号

```lua
local unit = game.units.get(0) -- 集合函数：点
if unit then
  unit.hp = 100               -- 属性赋值
  unit:update {level=5}       -- 对象方法：冒号
  unit:heal()
end
local cell = game.map.cell(0, 0) -- 地图函数：点
```

普通对象是代理，不是完整数据表。只访问定义过的属性；拼错名字会报错。不要用 `pairs(unit)`、`#unit`、`rawset` 等方式推断或绕过属性，也不要把代理直接写进会话状态。

### 5.2 下标约定

| 内容 | 起点 |
| --- | --- |
| 集合行号、`object.index`、格子下标、地图 x/y | 0 |
| 数字路径中的 `[行号]`、`.结构体成员` | 0 |
| JSON 宿主数组操作的下标、行为树节点路径中的值 | 0 |
| 普通 Lua 数组、`params`、`all()` 的结果数组、字节数组 | 1 |
| `editor.binary` 的字节偏移 | 0 |

部队 `agent_id` 和势力 `id` 是业务身份，`index` 是当前行号，两者不能互换。删除或排序会改变行号；改 ID 也不会自动修正所有其他对象里的引用。

### 5.3 `nil`、0、false 和空表

| 值 | 常见含义 |
| --- | --- |
| `nil` | 未写字段、缺少对象，或明确删除可选内容 |
| `0` | 已写入的数值零 |
| `false` | 已写入的布尔否 |
| `{}` | 普通空 Lua 表；赋给可选配置时表示保证配置存在 |

Lua 中 0 为真，false 与 nil 为假。检查字段是否存在，用 `value ~= nil`，不要用 `if value then` 代替存在性判断。给允许 false 的值提供默认值时，不要直接用 `value or true`。

```lua
local general = unit:ensure("general", {id=0, active=false})
general.parameter_2 = nil -- 删除可选表中的成员，其他成员保留
unit:clear("general")     -- 删除整份将领配置
```

`update` 是局部更新：只修改传入表实际包含的键，其他已知和未知成员保留。但 Lua 表不保留值为 nil 的键，因此 `unit:update {play_mode=nil}` 无法表达删除。删除标量请直接赋 `unit.play_mode=nil`，删除整组请用 `clear`。

结构体没有可删除的独立成员槽，已有成员清空按其规则写零；位段等属性可能拒绝 nil。地图布尔与地形值也不支持任意清空。不要把所有属性都当作可选表标量处理。

## 6. 对象接口参考

下列是当前公共对象的主要接口。更精确的属性声明见 [api/game.lua](api/game.lua)，具体映射以对象模块和公共字段目录为准。属性名是编辑器当前研究解释，不保证已经验证全部游戏语义。

### 6.1 普通集合

适用于 `units`、`factions`、`events`、`targets`、`reinforcements`、`weather`、`routes` 和对象工厂创建的普通表向量集合。行为树集合另见第 14 节。

| 接口 | 说明 |
| --- | --- |
| `collection.count()` | 当前行数 |
| `collection.get(index)` | 按 0 起行号取代理；nil 或未找到时返回 nil |
| `collection.each([predicate])` | 返回迭代器；筛选函数接收对象 |
| `collection.all([predicate])` | 当前对象的 1 起数组，元素仍是代理 |
| `collection.ensure()` | 保证向量存在，不创建行 |
| `collection.create([values])` | 新建一行并局部设置属性，返回对象 |
| `collection.remove(index或object)` | 删除指定行，并执行该集合的清理回调 |
| `collection.remove_where(predicate)` | 先筛选，再倒序删除；返回主集合删除行数 |
| `collection.move(from,to)` | 按 0 起行号移动 |
| `collection.copy(index或object,key)` | 复制到命名剪贴板；index 为 nil 时清除此 key |
| `collection.paste(key)` | 追加剪贴板中的节点副本并返回对象 |
| `collection.define_field(name,descriptor)` | 加载阶段增加属性 |
| `collection.define_method(name,fn)` | 加载阶段增加对象方法 |

`paste` 是节点复制，不等同于 `create`，不执行新建默认值和关联回调，也不会分配新的业务 ID。复制身份对象后应显式处理 ID 和关联规则。不要把不相容的集合共用一个剪贴板 key。

通用对象方法为 `object:update(values)`、`object:ensure(name[,values])`、`object:clear(name)`。后两个只用于可选配置组，不能用于普通标量或图层。

### 6.2 部队 `game.units`

| 分类 | 属性或方法 |
| --- | --- |
| 位置与身份 | `index`、`cell_index`、`faction`、只读 `agent_id`、`unit:set_id(id)` |
| 基础属性 | `type_id`、`hp`、`max_hp`、`level`、`stack`、`direction`、`mobility` |
| 其他属性 | `parameter_8`、`parameter_9`、`play_mode`、`ai_target`、`faction_extra`、`general_id` |
| 可选配置 | `general`、`behavior`、`special` |
| 方法 | `unit:heal()`、`unit:move(x,y)` |
| 集合辅助 | `selected(ctx)`、`at_cell(cell_index)`、`index_at_cell(cell_index[,last])`、`next_id()`、`remove_at_cell(cell_index)` |

`general` 包含 `id/active/parameter_2`。`behavior` 包含 `id/parameter_0/parameter_2/radius/parameter_4/center_cell/parameter_6`。`special` 包含 `id/parameter_1/hp/max_hp/parameter_4/parameter_5`。

`each(faction_id)` 和 `all(faction_id)` 是部队集合额外支持的筛选形式。`unit:heal()` 要求存在最大生命值；`move` 根据当前地图尺寸计算格子索引。

### 6.3 势力 `game.factions`

属性包括只读 `id`、`country`、`camp`、`gold`、`tech`、`income_multiplier`、`damage_multiplier`、`hp_multiplier`、`is_ai`、`color`，以及 `parameter_5/alignment_1/alignment_2/config_id/general_flag/config_ref`。

颜色使用 `faction.color.r/g/b/a`，或 `faction.color={r=...,g=...,b=...,a=...}`，通道范围 0–255。集合支持 `by_id(id)`、`selected(ctx)`；修改身份使用 `faction:set_id(id)`。

创建势力会设置默认值并建立当前实现管理的两类关系行；删除和移动也会处理这些关系行。这不代表所有跨对象关系都已封装，例如删除势力不会自动替你重新分配每支部队的归属，修改 ID 也不是全局引用迁移。

### 6.4 事件与地标 `game.events`

事件属性为 `cell_index`、`parameter_1`、可选 `building` 和 `fort`。

`building` 包含 `flag/type_id/extra/owner/dx/dy/parameter_6`；`fort` 包含 `id/parameter_3`。事件方法包括 `event:prepare_building()`、`event:is_building()`、`event:is_fort()`。集合辅助包括 `index_at_cell(cell[,kind,last])`、`remove_landmarks(cell)`。

识别规则有明确条件：`is_building()` 要求建筑 flag 存在，`is_fort()` 要求工事 id 或 parameter_3 存在，零值也算存在。空配置与完整地标并不等价。定位选择、扩图识别和显式删除保留各自现有规则，不能假设它们的条件完全相同。

### 6.5 地图、格子与图层

地图属性为只读 `width/height` 和可写 `left_margin/top_margin/play_width/play_height`。地图函数均采用点调用：

```lua
local cell = game.map.cell(2, 3)
local same = game.map.cell_at_index(3 * game.map.width + 2)
local optional = game.map.try_cell_at_index(-1) -- 返回 nil
for current in game.map.cells() do
  -- current 是当前调用中的格子代理
end
```

格子有只读 `index/x/y`，以及 `climate`（0–7）、`variant`（0–31）、`sea`、`playable`。三个图层为 `main`、`secondary`、`decor`：

```lua
cell.main = {id=7, variant=0, dx=-2, dy=3}
if cell.main.present then
  cell.main:update {dx=0, dy=0}
end
cell.decor = nil -- 明确删除装饰层
```

图层代理始终可取，实际有无图层看 `.present`；图层不存在时属性为 nil。写具体属性或 `present=true` 可创建图层；仅赋 `{}` 没有属性写入，不能保证创建。`id/variant` 为 0–255，`dx/dy` 为 -128–127。

整体扩缩使用 `game.map.resize {left=1,right=0,up=0,down=0}`，数值表示各边增加的格数，负数可裁剪；当前总尺寸上限为 500×500。它同时处理实体位置和紧凑地形，包含既有的同格实体取舍及越界处理。它不是纯粹改两个尺寸字段，边界无效时当前实现可能直接返回；使用后应核对结果。

### 6.6 全局配置及其他集合

| 入口 | 属性 |
| --- | --- |
| `game.stage` | `round_limit`、`fog` |
| `game.targets` | `type/value/param1/param2/flag` |
| `game.reinforcements` | `cell/faction/is_key/flag` |
| `game.weather` | `type/start/duration` |
| `game.routes` | `flag/cells` |

`game.stage.fog` 是经过转换的布尔语义，不是原始字段值。路线 `cells` 是普通 Lua 数组副本，读取后修改必须整体赋回；nil 表示删除字段，`{}` 表示已写入的空数组。

## 7. 常用工具写法

### 7.1 批量局部修改

下面是完整工具文件，可独立安装。只修改经验，不重写堆叠编制或其他配置：

```lua
editor.tool {
  id="user.add_level", title="所有部队增加经验", target="all_units",
  params={{id="amount",label="增加值",type="integer",default=1,min=0,max=255}},
  run=function(unit,params)
    unit.level=math.min(255,(unit.level or 0)+params.amount)
  end,
}
```

### 7.2 批量删除

完整工具使用 `stage` 执行一次，再由集合筛选删除：

```lua
editor.tool {
  id="user.remove_faction_units", title="删除指定势力部队", target="stage",
  confirm="将删除指定势力在部队集合中的全部部队，包括地图外部队。",
  params={{id="faction",label="势力",type="faction"}},
  run=function(_,params)
    local removed=game.units.remove_where(function(unit)
      return unit.faction==params.faction
    end)
    assert(removed>0,"没有找到该势力的部队")
  end,
}
```

普通 `each` 在开始时捕获行数，不适合边遍历边增删同一集合。`remove_where` 先选中对象再倒序删除，避免漏掉相邻行；筛选函数只负责判断，不要在其中增删、移动或修改对象。

### 7.3 可选配置与数组

以下片段放在工具 `run` 或写动作内：

```lua
local unit=assert(game.units.get(0),"没有部队")
local general=unit:ensure("general") -- 不重置已有成员
general.id=7
general.active=false

local route=game.routes.get(0)
if route then
  local cells=route.cells or {}
  cells[#cells+1]=0
  route.cells=cells -- 数组副本需要赋回
end
```

### 7.4 创建对象

同样放在工具或动作内。字段范围和关联有效性由脚本根据实际关卡决定：

```lua
local unit=game.units.create {
  cell_index=0, faction=0, type_id=101,
  hp=100, max_hp=100, level=0, stack=0,
}
-- create 为部队准备基础结构并分配 ID。
-- 若需要特定 ID，显式调用 unit:set_id(...) 并自行检查冲突和引用。
```

不要把“当前写入类型合法”当作“游戏规则已经合法”，例如脚本不会全面检查兵种、势力和行为树之间的业务约束。

## 8. 扩展现有对象

### 8.1 给对象增加属性与方法

在加载阶段使用公共工厂。下面是研究扩展片段，假定已经确认部队 `/33` 是 `u16`，并已提供相应物理类型声明：

```lua
local objects=editor.modules.objects
game.units.define_field("research_rank",objects.scalar("/33","u16"))
game.units.define_method("research_promote",function(unit,delta)
  unit.research_rank=(unit.research_rank or 0)+delta
end)
```

工具中随后可以写 `unit:research_promote(1)`。`/33` 相对于该部队行；它不是根表字段 33，也不是文件字节偏移。超出 `u16` 范围时写入报错，不会自动截断。

不能重复定义属性、方法或覆盖 `index/update/ensure/clear` 等名称。要修正已有解释，应修改字段目录或所属模块，避免用另一套同名定义掩盖变化。

### 8.2 属性描述工厂

| 工厂 | 用途与约束 |
| --- | --- |
| `objects.scalar(path,kind[,readonly,layout])` | 数值/布尔标量及结构体成员；结构体布局必须已知，必要时提供完整成员类型 |
| `objects.named(id[,readonly])` | 使用公共字段目录中的路径、位段和文档类型 |
| `objects.array(path,kind)` | 标量数组，读取副本、整体写回 |
| `objects.optional(group_id,label,fields[,prepare])` | 字段目录中的可选配置组，支持 ensure/clear |
| `objects.packed(path,shift,default,label,layout)` | 现有 8 位打包属性辅助；不是任意位宽和存储类型的通用声明 |

`objects.optional` 的第一个参数是目录 ID，不是数字路径。可选组及子字段应先在字段目录中登记。新位段优先用目录的 `shift/width` 表达；直接调用 `packed` 前应核对它当前选择存储类型的规则。

属性描述本质是 `{get=function(anchor)...end,set=function(anchor,value)...end}`。需要自定义转换时可自行构造，但锚点和 `editor.internal` 属于较低层接口；应在独立对象模块内封装并验证，避免在每个工具中重复实现。

## 9. 新增对象集合

假设根字段 `/35` 已声明为 `ResearchRecord` 的表向量，每行字段 0/1 为 ushort：

```lua
local objects=editor.modules.objects
game.research_records=objects.collection {
  path="/35",
  label="研究记录",
  fields={
    owner=objects.scalar("/0","u16"),
    rank=objects.scalar("/1","u16"),
  },
}
```

这会得到第 6.1 节的通用集合操作，不会自动生成独立 XML 页面。需要菜单操作时声明 `target="stage"` 的工具；需要页面时增加用户布局。

### 9.1 生命周期回调

| 集合选项 | 用途 |
| --- | --- |
| `fields` | 对象属性描述表 |
| `methods` | 对象方法，首参数为对象，调用时使用冒号 |
| `api` | 额外集合函数，点调用，不能覆盖已有集合函数 |
| `prepare(anchor)` | 新行追加后准备物理结构 |
| `initialize(object)` | 写默认值，在调用方属性之前执行 |
| `after_create(object)` | 调用方属性设置后创建关联数据 |
| `before_remove(object)` | 删除行前清理关联数据 |
| `after_move(object,from,to)` | 移动完成后调整关联顺序 |
| `matches(object,filter)` | 解释非函数筛选参数 |

创建顺序为：追加行 → prepare → initialize → update 调用方属性 → after_create。删除调用 before_remove 后再删除对象当前所在行。回调属于外层动作事务，不各自建立独立事务。

带唯一 ID 或关联表的集合应把规则集中放在这些回调和对象方法里，工具只调用公共接口。不过通用 `paste` 不执行这些回调；需要复制业务对象时，最好编写明确的复制方法处理身份与关系。

### 9.2 完整示例

[examples/research_objects.lua](examples/research_objects.lua) 是完整合成示例，包含 schema 声明、现有部队新属性、新方法、新集合和一个批量工具。它未加入自带布局，使用的是虚构字段号，不能把它直接视为真实关卡格式结论。

## 10. 物理类型与公共字段目录

这两者解决不同问题：schema 决定“这些字节如何读写”，目录决定“这个具名属性对应哪个槽、哪几位，以及研究依据是什么”。只给对象起名不能补齐未知物理类型。

### 10.1 读取前声明物理类型

下面可与第 8–9 节组合；字段位置是合成示例：

```lua
editor.format.schema {
  id="my_research.schema",
  definition=[[
    table AIAgent { research_rank:ushort (id:33); }
    table Root { research_records:[ResearchRecord] (id:35); }
    table ResearchRecord {
      owner:ushort (id:0);
      rank:ushort (id:1);
    }
  ]],
}
```

| 声明规则 | 当前行为 |
| --- | --- |
| table 字段 | 每项必须明确 `(id:N)`，范围 0–511；只合并列出的字段 |
| 同一 table 字段被多次声明 | 后加载的声明生效，最终类型与名称仍需通过验证 |
| 同名 struct | 整体替换，必须给出完整成员；当前扩展成员限标量 |
| 类型引用 | 全部脚本加载后验证，可引用后声明类型 |
| 不支持的声明 | include、root_type、新 enum、table/struct 相互转换等 |
| 大小限制 | 单片段 100 万字符，总 schema 文本 800 万字符 |

`.fbs` 使用 `ushort/uint/ubyte` 等类型名，编辑 API 使用 `u16/u32/u8` 等短名。二者不要混用。声明字符串或特殊结构不等于已开放相应编辑接口；结构体沿用核心现有布局规则，不能声明任意填充和对齐。

### 10.2 公共字段目录

目录 JSON 保存稳定 ID、owner、path，可选 parent、kind、shift/width、revision、confidence、evidence、note。要让新属性和 XML 共享映射，可登记目录后使用 `objects.named("my.field")`，XML 使用 `field="my.field"`。

用户目录通过布局加载：

```xml
<editorLayout format="1">
  <fields src="fields/research.json"/>
</editorLayout>
```

覆盖按 ID 替换整项定义，不是仅合并某个 JSON 属性。修改父组路径会传递到子项；parent 与子项应有相同 owner。目录中的置信度记录语义研究程度，不会替代物理类型验证，也不会自动决定能否导出。

具名编辑的有效目录和使用字段会记录在工作文档的来源信息中；游戏 BTL 不存放这些编辑器元数据。详见 [公共字段目录说明](fields/README.md)。

### 10.3 推荐接入顺序

1. 记录样本、字段位置、类型判断和仍不确定的内容。
2. 用 schema 声明正确读取新物理字段，重新打开样本。
3. 定义目录及对象属性，或在研究初期用局部数字路径封装。
4. 编写工具；需要固定表单时再补 XML。
5. 验证未写、零值、边界、往返、未知内容保留与游戏表现。

## 11. 自定义载荷与二进制接口

### 11.1 适用对象

载荷接口处理文档中的普通 `u8` 向量，可以在 Lua 中解释内部头部、数值和位段。它不接管整个 BTL 文件，也不自动识别任意未知块。现有带特殊编码标记的向量（例如国家行为树）使用对应专用接口。

### 11.2 编解码器声明和调用

以下是声明片段，假设载荷至少有 8 字节，以 0x7B 开头，偏移 1 是小端 u16：

```lua
editor.format.codec {
  id="my_research.packet",
  revision="1",
  decode=function(bytes)
    assert(#bytes>=8 and bytes[1]==123,"载荷头或长度不符合预期")
    return {value=editor.binary.read(bytes,1,"u16"),bytes=bytes}
  end,
  encode=function(packet)
    editor.binary.write(packet.bytes,1,"u16",packet.value)
    return packet.bytes
  end,
}
```

在工具或动作内调用：

```lua
local packet=editor.format.read("my_research.packet","/31")
packet.value=513
editor.format.write("my_research.packet","/31",packet)
```

`read` 复制字节并返回解码后的 Lua 值。修改 Lua 值不修改文档，必须显式 `write`；write 完整校验编码结果后替换字节向量。目标向量必须存在，新载荷可先用 `editor.data.ensure_vector(path,"u8")` 创建。

打开文件不会自动运行全部 decoder，保存不会执行 encoder 或提交闭包里的对象。编解码函数只能处理输入值，使用基础运算、位运算和 `editor.binary`；不能访问文档、会话状态或嵌套调用其他 codec。

保留原始字节再局部修改，适合暂时不了解全部成员的载荷。若编码器完全重新生成数组，就要自己保证未修改内容、长度、校验和和内部引用仍然正确。

### 11.3 字节缓冲区

| API | 行为 |
| --- | --- |
| `editor.binary.create(size)` | 新建填零的字节数组 |
| `editor.binary.read(bytes,offset,kind[,order])` | 读取标量，默认 `le`，可指定 `be` |
| `editor.binary.write(bytes,offset,kind,value[,order])` | 原地修改 Lua 数组，不扩容、不直接写文档 |

支持 `u8/i8/u16/i16/u32/i32/u64/i64/f32/f64`。字节数组连续、从 1 开始，每项为 0–255 整数；偏移从 0 开始。缓冲区及载荷上限为 200 万字节。浮点接口只接受有限值；特殊位模式需要按原字节保留。

```lua
local bytes=editor.binary.create(8)
editor.binary.write(bytes,0,"u64","18446744073709551615","be")
assert(editor.binary.read(bytes,0,"u64","be")=="18446744073709551615")
```

64 位整数读写使用十进制字符串以保证精度。越界、错误类型和非法输出会报错；单次 binary 写入验证失败不会留下部分缓冲区修改。

### 11.4 研究版本与来源

成功且确有修改时，文档记录载荷路径、codec ID、revision 和定义 codec 的源文件 SHA-256。这些记录随历史和工作 JSON 保存，不写进游戏 BTL。记录按路径识别，不会随着集合行移动自动跟随对象。

同一路径已记录来源后，换 codec、版本或源文件再读写会被拒绝。应使用原脚本，或保存当前成果后以新脚本重新打开 BTL。即使只是修改 codec 所在文件的其他内容，也可能改变指纹；依赖其他文件的算法变化则需要主动增加 revision，当前指纹不会追踪所有依赖。

完整示例及宿主接入见 [格式扩展](格式扩展.md)、[examples/research_packet.lua](examples/research_packet.lua)。

## 12. 动作、定位器与 XML 页面

工具适合菜单和批量操作；动作适合页面上的按钮或单字段交互。两者最终共用文档事务。

### 12.1 两种动作

```lua
-- 按钮动作：在执行时取得当前文档对象。
editor.action("user.heal_first",function(ctx)
  local unit=assert(game.units.get(0),"没有部队")
  unit:heal()
end)

-- 字段动作：get 只读，set 获得 ctx.value。
editor.action("user.round_limit",{
  get=function(ctx) return game.stage.round_limit end,
  set=function(ctx) game.stage.round_limit=ctx.value end,
})
```

### 12.2 上下文

| 成员 | 含义 |
| --- | --- |
| `ctx.value` | 单字段 setter 当前值 |
| `ctx.input` | 表单输入，按 XML 字段 id 索引；工具也提供上下文输入 |
| `ctx.index` | 当前列表行，或定位器返回的数值 |
| `ctx.cell_index` | 当前地图格子，可能为 nil |
| `ctx.unit_index/faction_index` | 显式列表选择，可能为 nil |
| `ctx.item` | 调用方提供的项目数据 |
| `ctx.object/ctx.path` | 依据当前绑定及定位器生成的对象或路径；并非所有调用都有 |
| `ctx.cache` | 当前读取范围共享的临时缓存，下一次刷新不能依赖它 |

不要假定地图选择、列表选择和业务 ID 是同一个值。写整份表单时，空输入往往有删除或归零的含义；批量工具应局部修改，不能直接复用整份表单覆盖所有值的逻辑。

### 12.3 定位器

```lua
editor.resolve("user.unit_at_cell",function(ctx)
  return game.units.index_at_cell(ctx.cell_index)
end)
```

定位器负责从当前选择找到目标，是只读函数。现有部队页面通过集合 bind 和定位器的行号定位对象。复杂的句柄和路径返回约定由宿主管理，新增页面优先参考同类现有页面。

### 12.4 一个完整的自定义页面

创建 `EditorLayout.user/layout.xml`：

```xml
<editorLayout format="1">
  <tabs>
    <tab id="user_research" title="研究工具" page="pages/research.xml"/>
  </tabs>
  <scripts>
    <script src="scripts/research_page.lua"/>
  </scripts>
</editorLayout>
```

`scripts/research_page.lua` 使用第 12.1 节的两个完整动作声明。再创建 `pages/research.xml`：

```xml
<page id="user_research">
  <section title="研究操作" kind="form">
    <field id="round_limit" label="总回合" widget="number"
           type="u16" action="user.round_limit"/>
    <actions>
      <action id="heal" label="恢复首支部队" script="user.heal_first"/>
    </actions>
  </section>
</page>
```

page id 必须与 tab id 一致；用户同 ID 的 tab 会替换自带页，新增页面应使用独立 ID。Lua 动作名必须与 XML 的 action/script 对应，否则控件可能被禁用。

普通具名字段可用 `field="unit.hp"`；原始路径可用 `bind`；自定义逻辑可用 `action`。字段目录绑定不能与原始 bind、type、位段或 action 混写。选择一种绑定方式后按对应规则定义控件。实际布尔字段需要表达未写时，可用 `widget="check" nullable="true"`；可选配置组启用开关则控制整组是否存在。

复杂列表、树和地形选板请参考 [现有页面](pages/stage.xml)、[部队页面](pages/unit.xml) 及对应脚本。不要假定 XML 可以直接表达任意 WinForms 控件或新的原生 handler。

## 13. 数字路径接口

用于接入新字段、尚未封装的数据和对象模块。工具中大量重复路径时，应考虑提取对象属性。

### 13.1 路径语法

```text
/6/0             根字段 6 下的字段 0
/6/0[2]          该向量的第 3 行
/6/0[2]/1.3      该行字段 1 的结构体成员 3
```

`/N` 是 table 字段，`[N]` 是 vector 元素，`.N` 是 struct 成员，都是结构索引，不是二进制偏移。根路径用于 `editor.data`，对象描述中的路径相对于对象锚点。

### 13.2 API 2 常用接口

| API | 参数与行为 |
| --- | --- |
| `data.get(path)` | 读取标量；缺失为 nil，不创建数据，不返回 table/vector 代理 |
| `data.exists(path)` | 判断目标是否存在，显式零和 false 也算存在 |
| `data.set(path,kind,value)` | 按明确类型写标量 |
| `data.count(path)` | 读取向量长度 |
| `data.row(path,index)` | 拼接行路径，不读取或创建该行 |
| `data.ensure_table(path)` | 保证 table 存在 |
| `data.ensure_struct(path,layout)` | 保证 struct 存在，layout 是完整成员短类型数组 |
| `data.ensure_vector(path,elem)` | 保证普通向量存在，table 用 `"table"` |
| `data.ensure_struct_vector(path,layout)` | 保证结构体向量存在并给出成员布局 |
| `data.append(path)` | 追加元素并返回 0 起下标，需有适用的向量定义 |
| `data.remove(path,index)` | 删除向量元素 |
| `data.move(path,from,to)` | 移动向量元素 |
| `data.fill(path,kind,values)` | 用连续 Lua 数组写入标量向量 |
| `data.get_integer(path)` | 整数标量读取为精确十进制字符串 |
| `data.set_integer(path,kind,text)` | 精确写入 `u64/i64`，text 必须是十进制字符串 |

这里 `data` 指 `editor.data`。API 2 对这些入口的参数数量有固定检查，不要套用旧全局接口的重载写法。

普通标量短类型为 `u8/i8/u16/i16/u32/i32/u64/i64/f32/f64/bool`。常规 Lua 数字的整数精确范围上限为 9007199254740991；精确 64 位数据应走字符串接口。普通数字路径字符串字段写入目前没有开放，不要使用猜测的 `kind="string"`。

低层 `set(...,nil)` 与对象层的存在性处理不完全相同，遍历路径时可能准备父级。研究脚本对缺失结构进行删除前应先检查存在性；涉及可选组时优先使用具名对象，避免制造空父表。

```lua
-- 放在写动作或工具内；适用于已确认具有相应物理类型的字段。
editor.data.set("/2/1","u16",30)
local text=editor.data.get_integer("/2/1")
assert(text=="30")
```

旧的 `editor.get/set/ensure/append/...` 与句柄重载仍用于兼容部分脚本。新增普通脚本优先选择 `game` 或固定参数的 `editor.data`，不要依赖未查证的旧重载。

## 14. 行为树与 JSON

Root 字段 10 是国家、部队和建筑共用的 FlexBuffers 树库，普通工具使用 `game.behavior_trees`。字符串按游戏的 GB18030 编码处理。它不是普通表向量工厂集合，没有完整的 each/remove_where 等通用方法。

```lua
-- 放在工具或写动作内。
local trees=game.behavior_trees
local tree
if trees.count()>0 then tree=trees.get(0) else tree=trees.create() end
tree.name="研究用行为树"
local child=tree:add_child({class="wait",id=0},false)
child.rounds=2 -- 整数，表示节点启动后的相对等待回合数。
```

行为树及节点支持 `btid/id/name/agent/class/method/result/count/rounds`、数组 `params` 和只读 `child_count`。`rounds` 是非负整数；`params=nil` 删除字段，`params={}` 保留空数组。方法有 `update(values)`、`node(path)`、`add_child(values[,with_children])`、`remove_child(index)`。`tree:node({0,1})` 表示第一个子节点的第二个子节点：Lua 路径表从 1 起，各路径值从 0 起。脚本作者需保证节点 ID 在树内唯一，btid 与对应三类对象的绑定一致。

原始载荷随工作文档、克隆和撤销保留；树内容未改变时保存复用原字节，修改后按 FlexBuffers 编码。编码失败会阻止导出，不再清空树库。未知类型或无法表示为 JSON 的内容保留原字节并拒绝树编辑；其他位置的 FlexBuffers 状态不自动当作树库处理。旧版工作 JSON 中已经丢失原字节的错误负数无法可靠自动修复，应从原 BTL 重新打开。

需要操作未知 JSON 键时使用较低层的接口：

| 接口 | 用途 |
| --- | --- |
| `editor.json.vec_count(path)` / `vec_at(path,index)` | 访问行为树向量及其中对象句柄 |
| `editor.json.vec_append(path)` / `vec_remove(path,index)` | 添加或删除整棵树 |
| `editor.json.get(handle,key)` / `set(handle,key,value)` | 访问 JSON 对象成员 |
| `editor.json.count(handle[,key])` | 数组长度，或对象中指定数组长度 |
| `editor.json.at(handle,index)` / `at(handle,key,index)` | 数组元素 |
| `editor.json.insert(handle,index[,value])` / `insert(handle,key,index[,value])` | 插入元素，省略 value 时创建对象 |
| `editor.json.remove(handle,index)` / `remove(handle,key,index)` | 删除数组元素 |
| `editor.json.object([table])` / `array([table])` | 在写动作内明确构造对象或数组 |
| `editor.json.null` | 写入 JSON null 的标记 |

`json.set(handle,key,nil)` 删除成员；写 JSON null 用 `editor.json.null`。空 `{}` 默认按数组解释，写空对象时应显式 `json.object()`。数组必须连续，空元素用 null 标记；混合字符串键和数组下标、循环引用和超过 64 层的结构会被拒绝。读取到的 JSON 对象/数组是宿主句柄，不能按普通 Lua 表直接操作。

## 15. 状态、剪贴板与对象寿命

### 15.1 对象代理只在当前调用内使用

部队、可选配置、格子、图层、迭代器和 JSON 句柄都绑定当前文档执行上下文。不要把它们放进全局变量、闭包或跨动作缓存。撤销、重新加载、切换文档或下次调用后应重新取得对象。

同一次动作中，集合代理跟随实际节点，移动或删除其他行后其 `index` 可反映新位置；已经删除的对象不能继续读写。`all()` 得到的是代理数组，不是独立数据副本，更不能当作跨调用快照。

需要记住目标时，保存普通 ID、坐标或数值，下次调用重新查找。业务 ID 仍可能被用户修改，保存行号也不保证长期身份稳定，脚本应处理目标不存在的情况。

### 15.2 会话状态

```lua
-- 写动作内；存普通数据，不存代理或函数。
editor.state.set("user.last_cell",0)
local previous=editor.state.get("user.last_cell")
editor.state.set("user.last_cell",nil) -- 删除该 key
```

`editor.state` 是宿主内的会话数据，不写入游戏 BTL，也不是文件配置存储。布局热加载创建新宿主，状态会丢失。失败动作会恢复状态；正常撤销文档编辑不会同步撤销此状态。读取可放在执行函数中，写入要求写动作。

Lua 全局或闭包变量不是可靠的持久状态：失败后 VM 会重建，源码会重新加载，变量恢复到加载初值。

### 15.3 命名剪贴板

低层接口为 `editor.clipboard.copy(key,path)`、`has(key)`、`clear(key)`、`paste(path,key)`；高层集合有 copy/paste 包装。剪贴板保存节点副本，粘贴复制为新的节点，不共享对象身份。复制、清除和粘贴都应放在写动作中。

剪贴板是宿主内部数据，不等同于操作系统文本剪贴板。失败会回滚剪贴板；文档撤销不会同时恢复剪贴板。新宿主也不会继承旧宿主的剪贴板。

## 16. 事务、错误与运行限制

### 16.1 整批成功或失败

一次工具运行中的所有对象及其回调共用事务。未捕获错误会回滚整个动作；Lua 和 C# 修改也可加入同一个外层文档事务。只有文档最终发生变化才增加历史记录，无变化的工具可以完成计数但不新增撤销项。

```lua
-- 写动作内：任何一支缺少最大生命，就拒绝整个批次。
for unit in game.units.each() do
  assert(unit.max_hp~=nil,"存在缺少最大生命的部队")
  unit:heal()
end
```

不需要手工备份已修改对象。需要补充判断时，可先检查完整批次再写入，使错误更容易理解，但没有必要为了回滚而复制所有字段。

### 16.2 pcall 不是子事务

Lua 可以捕获普通错误，但 `pcall` 不为其中的写入建立独立事务。如果先成功修改了一些值，再发生错误，随后被脚本捕获且正常结束，之前的修改可能提交。希望整个动作失败时，用 `error` 或 `assert` 把失败传播给宿主。

载荷编码结果和单次二进制写入有各自的先验证后写入保证，但不能据此推断任意一段 pcall 中的多步文档修改都会自动撤销。

### 16.3 只读与预算

getter 和定位器只读，且不创建文档快照。需要多字段共享计算时用 `ctx.cache` 存普通显示数据；不要在 getter 中“顺便补齐”字段。

宿主默认每次加载或执行有 500 万指令、2 秒的预算，也支持宿主侧取消令牌。预算由外层检查，不能通过 pcall 无限捕获后继续执行。编译、C# 回调和文档快照无法由 Lua 协程抢占，也没有严格内存配额。

运行时基于 MoonSharp，只开放基础、table、迭代器、string、math、错误处理和 metatable 模块。不要按完整桌面 Lua 环境假设 `io/os/package/require/debug`、LuaJIT FFI、原生扩展或系统命令可用。位运算使用 `editor.band/bor/bxor/lshift/rshift`，不依赖外部位运算库或特定 Lua 版本的运算符。

## 17. 排错与验证

### 17.1 常见问题

| 现象 | 优先检查 |
| --- | --- |
| 工具没有出现 | 是否放到实际运行副本的 user/tools，是否重新加载，是否有加载错误 |
| “只能在加载脚本时登记” | 是否在 run/getter 中调用 tool/schema/define_field 等登记入口 |
| 加载时无法访问文档 | 是否在文件顶层读取了部队、地图或 state |
| “没有选中对应对象” | target 与当前地图/列表选择是否匹配 |
| “没有属性” | 拼写、对象类型、模块加载顺序，是否错误使用旧内部接口 |
| “请使用对象:方法调用” | 对象方法是否误用了点 |
| “句柄已失效” | 是否跨调用保存代理，是否在删除对象后继续使用 |
| 路线数组修改后没变化 | 是否只改了副本，没有整体赋回 |
| update 没有清除字段 | nil 不会作为 Lua 表项保留，应直接赋 nil 或 clear |
| 全部跳过后工具报错 | 所有 run 都返回 false，或没有符合筛选的对象 |
| 类型声明已改但读法未变 | 是否重新打开 BTL；热加载不会重新解释文档 |
| 载荷版本不匹配 | codec ID、revision、源文件内容与文档记录是否一致 |
| 修改成功但导出被拒绝 | 是否仍有未决物理数据；Lua 成功不等于二进制可安全重建 |
| 导出可重读但游戏异常 | 字段语义、引用关系、校验规则或样本覆盖是否不足 |

错误通常包含 Lua 文件和行号，宿主 API 错误还会附带调用信息；属性写入错误会附对象标签和属性名。目前批量错误不保证自动给出业务 ID 和当前对象行，关键检查应主动提供上下文：

```lua
assert(unit.max_hp~=nil,
  "部队行 "..unit.index.."，ID "..tostring(unit.agent_id).."：缺少最大生命")
```

### 17.2 建议的验证顺序

1. **加载**：工具和页面登记成功，类型声明通过验证。
2. **局部修改**：只改目标字段，未涉及成员保持原样。
3. **缺失和边界**：分别验证未写、0、false、空列表、上下界和非法输入。
4. **失败回滚**：在批次后半段制造错误，确认前面修改也回滚。
5. **历史**：撤销和重做恢复完整文档，检查关联行及来源信息。
6. **保存重读**：导出 BTL，以相同解释重新打开，核对值和未知数据。
7. **独立验证**：对照原始字节、独立预期或已确认样本；读写两端可能共享同一错误。
8. **游戏验证**：核对实际效果，之后再提高字段语义的置信度。

日常小工具不必每次跑全套工程测试。新增类型、布局、编码或关联规则时，应补有代表性的回归用例，并记下样本来源和研究依据。

仓库相关测试位于 `tests/FrontEdit.Tests`，其中 `GameToolsTests`、`ScriptApiTests`、`ScriptFormatTests`、`ObjectModuleTests` 覆盖对象、事务、格式和扩展；`tests/XmlUi.Smoke` 检查真实界面流程。测试通过能证明所覆盖行为一致，不能代替游戏格式研究结论。

## 18. 维护规范与能力边界

### 18.1 文件归属

| 位置 | 当前职责 |
| --- | --- |
| `scripts/common/对象工厂.lua` | 代理、属性描述、集合、可选配置与扩展机制 |
| `scripts/common/游戏入口.lua` | game 命名空间和工具范围分发 |
| `scripts/objects/部队.lua` | 部队属性、配置、方法和集合规则 |
| `scripts/objects/势力.lua` | 势力属性、默认值及关系行处理 |
| `scripts/objects/事件.lua` | 事件、建筑、工事和识别条件 |
| `scripts/objects/关卡.lua` | 全局配置、目标、增援、天气和路线 |
| `scripts/objects/地图.lua` | 地图、格子、图层和地图公共函数 |
| `scripts/common/扩图规则.lua` | 扩图时实体的保留、删除和坐标映射 |
| `scripts/common/行为树对象.lua` | 国家行为树及节点 |
| `scripts/unit/配置表单.lua` | 整份部队表单的空值与开关规则 |
| `scripts/ui/字段绑定.lua` | 需要动作逻辑的界面字段绑定 |
| `scripts/tools/分配单位UID.lua` | 默认菜单：按地块顺序分配单位 UID |
| `scripts/common/单位UID.lua` | UID 分配规则及已知引用维护 |
| `examples/常用工具.lua` | 生命、经验、金币和地形示例，默认不加载 |
| `api/game.lua` | 编辑器类型提示，不能作为运行脚本加载 |

旧的 `common/游戏对象.lua`、`业务对象.lua`、`地图操作.lua` 及部分单项配置辅助脚本已被上述模块替代。不要照旧文档手工加载这些文件；以当前 `layout.xml` 为准。`editor.modules.game_model`、共享全局 `write_unit_*` 等旧内部组织方式也不应继续使用。

### 18.2 推荐写法

- 普通工具局部修改对象，不复制整份表单和物理布局。
- 一个对象的映射和业务规则集中在所属模块；扩展通过 define_field/define_method 登记。
- 多个脚本共享功能时，用 `editor.modules.my_module` 显式导出，并在使用处 assert 依赖存在。
- ID 和名字带项目命名空间；研究声明记录版本和依据，未知语义保持中性命名。
- 需要保留的未知字段或载荷字节继续保留，避免为了修改一个已知值而重建全部内容。
- 结构修改使用集合接口及其回调，避免跳过关联清理；跨对象一致性仍需明确编写。

仓库 `.luarc.json` 把 [api/game.lua](api/game.lua) 配为 Lua 编辑器类型库。该文件只有类型说明，不是运行入口，不要放进 user/tools 或 layout。扩展可补如下说明帮助编辑器理解新属性：

```lua
---@class GameUnit
---@field research_rank integer?
---@field research_promote fun(self:GameUnit,delta:integer)
```

类型注释不创建运行时属性，也不替代 schema 或测试。当前类型库是主要对象的辅助说明，不是宿主所有旧重载的完整定义。

### 18.3 纯 Lua 能做到哪里

| 场景 | 当前处理方式 |
| --- | --- |
| 已有对象的批量修改、新工具和参数窗口 | 纯 Lua |
| 已支持物理类型的新字段、普通 table 向量 | Lua schema + 对象扩展；固定页面可加 XML |
| 字段路径和位段研究修订 | 字段目录或对象映射；物理类型变化需重新读取 |
| 已暴露普通字节载荷的新内部规则 | Lua codec + binary；复杂算法还需自行实现 |
| 普通字段字符串写入、新底层类型 | 当前可能需要补 C# 接口或核心支持 |
| 特殊 struct 对齐/填充、任意未知偏移块 | 需要进一步研究和底层支持 |
| 新的外层容器、通用压缩库、任意文件访问 | 当前没有通用纯 Lua 接入口 |
| 自动迁移、完整游戏规则检查、任意新 UI 控件 | 尚未提供通用实现 |

新增研究结果时，先判断变化落在哪一层，再扩展最小的对应位置。当前设计适合持续演进已知 FlatBuffers 结构和独立载荷，不承诺任何未知二进制格式都能仅靠脚本处理。

进一步参考：[对象扩展](对象扩展.md)、[格式扩展](格式扩展.md)、[公共字段目录](fields/README.md)、[Lua 扩展能力分析](../docs/Lua扩展能力分析.md)。
