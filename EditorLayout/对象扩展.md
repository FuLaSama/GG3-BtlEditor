# Lua 对象层的组织与扩展

安装、工具声明、完整对象参考、XML、事务与排错见 [Lua 开发手册](脚本编写.md)。本页集中说明对象工厂和模块扩展。

公共对象沿用 `unit.hp`、`unit:heal()`、`game.units.get(0)` 等写法。对象方法采用冒号调用，集合与地图函数采用点调用。新增普通属性和表向量对象可通过公共工厂扩展，不必修改 C#。

## 1. 模块归属

| 位置 | 职责 |
| --- | --- |
| `scripts/common/对象工厂.lua` | 属性描述、代理、集合、可选配置与加载阶段扩展入口 |
| `scripts/common/游戏入口.lua` | `game` 命名空间和工具作用范围分发 |
| `scripts/objects/部队.lua` | 部队全部属性、可选配置、身份与集合操作 |
| `scripts/objects/势力.lua` | 势力全部属性、默认值和关联行清理/排序 |
| `scripts/objects/事件.lua` | 事件、建筑、工事及相关识别规则 |
| `scripts/objects/关卡.lua` | 全局配置、目标、增援、天气和路线 |
| `scripts/objects/地图.lua` | 地图、格子、图层和地图方法的组装 |
| `scripts/common/扩图规则.lua` | 扩图时实体的保留、删除与坐标重映射 |
| `scripts/common/行为树对象.lua` | JSON 行为树与节点 |
| `scripts/unit/配置表单.lua` | XML 整份表单保存的空值和开关规则 |

加载顺序以 `layout.xml` 为准：工厂和入口先加载，各对象在所属模块一次定义完整，地图显式引用扩图规则。用户工具在这些模块之后加载。页面通过 `editor.modules.unit_forms/bt_forms` 使用表单辅助函数，不使用共享全局函数。

## 2. 给现有对象增加属性或方法

加载阶段可以使用 `game.units.define_field`、`define_method`；其他普通表向量集合也有这两个入口：

```lua
local objects = editor.modules.objects
game.units.define_field("research_rank", objects.scalar("/33", "u16"))
game.units.define_method("research_promote", function(unit, delta)
  unit.research_rank = (unit.research_rank or 0) + delta
end)

-- 工具 run 内：
-- unit:research_promote(1)
```

这里 `/33` 是相对于部队行的数字路径。完整合成示例见 [research_objects.lua](examples/research_objects.lua)，其中还声明了物理类型并新增研究记录集合和工具。示例字段是虚构的，不是已经确认的游戏字段。

已有类型已正确读取时，只需补充属性描述；新物理字段还需在读取前通过 `editor.format.schema` 声明，详见 [格式扩展](格式扩展.md)。公共字段目录已有定义时，使用 `objects.named("字段ID")` 复用位置、类型及位段解释。

扩展只能在脚本加载阶段登记。属性和方法名不能重复，也不能占用 `index/update/ensure/clear`；拼错属性仍会报错。有意修改已有字段的研究解释，应修改字段目录或所属对象模块，不通过覆盖同名扩展悄悄替换。失败加载会重建先前有效的运行时，去掉未完成的扩展。

## 3. 声明新集合

```lua
local objects = editor.modules.objects
game.research_records = objects.collection {
  path = "/35",
  label = "研究记录",
  fields = {
    owner = objects.scalar("/0", "u16"),
    rank = objects.scalar("/1", "u16"),
  },
}
```

这是一张普通 table 向量。工厂提供 `ensure/count/get/create/each/all/remove/remove_where/move/copy/paste`，以及 `define_field/define_method`。行号从 0 开始，`all()` 返回 1 起 Lua 数组，其中的对象仍是绑定文档节点的代理，寿命限当前调用。

| 属性描述 | 用途 |
| --- | --- |
| `objects.scalar(path,kind[,readonly,layout])` | 普通数值、布尔或结构体成员；结构成员需要现有布局或完整布局说明 |
| `objects.named(id[,readonly])` | 公共字段目录中的属性或位段 |
| `objects.array(path,kind)` | 标量数组；读取为副本，修改后整体赋回 |
| `objects.optional(group_id,label,fields[,prepare])` | 字段目录中的可选配置组，支持 ensure/clear |
| `objects.packed(path,shift,default,label,layout)` | 现有的 8 位打包属性工厂；其他位宽可自行构造 get/set 描述 |

自定义描述是一张含 `get(anchor)` 和 `set(anchor,value)` 的表；锚点由工厂管理，普通工具无需接触。

集合的 `methods` 定义对象方法，第一个参数是对象；`api` 定义额外集合函数，不覆盖标准集合方法。需要默认值或关联数据时可提供以下回调：

| 回调 | 执行时机 |
| --- | --- |
| `prepare(anchor)` | 追加新行后，写入所需物理结构 |
| `initialize(object)` | 设置新对象默认值，在调用方提供的属性之前执行 |
| `after_create(object)` | 属性设置完成后创建关联行 |
| `before_remove(object)` | 删除当前行之前清理关联数据 |
| `after_move(object,from,to)` | 行移动完成后调整关联顺序 |
| `matches(object,filter)` | 支持非函数筛选条件；部队用它保留 `each(faction_id)` 写法 |

这些操作加入调用方现有事务。未捕获失败会回滚整个动作；宿主不为每个工厂回调单独建立事务。

## 4. 常见操作

```lua
-- 保证将领配置存在；已有属性和未展示成员保留。
local general = unit:ensure("general", {id=7, active=false})
general.parameter_2 = 0

-- 明确删除整个可选配置。
unit:clear("general")

-- 先筛选，再倒序删除，不会漏掉相邻行。
local removed = game.units.remove_where(function(unit)
  return unit.faction == 3
end)
```

`ensure/clear` 只适用于可选配置组，不用于普通标量或图层。清除图层仍可写 `cell.main=nil`；创建图层时赋具体属性表或设置 `present=true`。

`remove_where` 使用当前集合的 `remove` 及其关联清理规则；删除势力会同步清理国家关系和关联行。筛选函数应只作判断，不能在其中增删或排序集合。筛选完成前不会开始删除，返回值是删除的主集合行数。

`each(function(object) ... end)` 可筛选普通集合，部队同时保留 `each(faction_id)`。普通遍历仍不适合改变所在集合长度；跨动作保存的是 ID、索引或坐标，下一次调用重新取得对象。

## 5. 扩图与格式解释

扩图 Lua 通过 `event:is_building()`、`event:is_fort()` 和具名坐标属性判断、搬运实体。识别逻辑在事件模块中使用公共字段目录，移动建筑或工事配置组后，扩图会采用新位置。

识别条件保留既有语义：建筑要求 flag 成员存在，工事要求 id 或 parameter_3 存在；零值也算存在。空配置组仍按原扩图逻辑处理，不等同于完整地标。界面的定位选择和显式删除配置仍遵循各自的既有规则。

紧凑地形由 `TerrainEdits.Project/Store/Resize` 处理；脚本不再重复遍历图层标志和属性向量。扩图前提交待写图层投影，搬运时保留完整结构体、类型布局和未关联尾部，然后清理缓存供后续格子访问重新定位。原有同格实体取舍等业务规则保留。

## 6. 类型提示与迁移

[api/game.lua](api/game.lua) 是供 Lua 编辑器读取的类型说明，包含对象、集合、工厂、参数和返回值。仓库 `.luarc.json` 把它配置为类型库。它不是运行脚本，不要登记到布局或复制到用户工具目录。扩展自己的对象时可参考示例中的 `---@class`、`---@field` 和 `---@type` 注释。

现有 `editor.tool`、动作名、具名属性、集合函数和冒号方法保持兼容。对象模块已替换旧 `common/游戏对象.lua`、`业务对象.lua`、`地图操作.lua`；整份部队表单辅助逻辑合并到 `unit/配置表单.lua`，地形层名由地图模块提供。如果外部宿主手工列出内置脚本文件，需按新的 `layout.xml` 加载依赖。旧 `editor.modules.game_model` 及全局 `write_unit_*`、`terrain_layers` 等内部组装方式已移除，新增扩展使用本页的公共入口。
