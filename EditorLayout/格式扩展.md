# 用 Lua 扩展字段类型和字节载荷

工具编写、对象接口、加载流程与验证方法见 [Lua 开发手册](脚本编写.md)。本页集中说明物理类型和载荷格式扩展。

本接口是在现有 API 2 上新增的能力。扩展文件放入 `EditorLayout.user/tools`，重新加载布局后，**重新打开关卡**，让读取器采用新的类型声明。无需修改 C# 或重新编译编辑器。

需要把新字段封装成具名属性、定义新集合或使用批量删除辅助方法时，参见 [Lua 对象扩展](对象扩展.md)。

完整的可运行合成示例见 [research_packet.lua](examples/research_packet.lua)。它使用虚构的 Root 字段 31 和自定义字节载荷，不代表已经确认的游戏格式；安装到真实关卡环境前应替换为实际研究结论。

## 1. 读取前声明物理类型

```lua
editor.format.schema {
  id = "my_research.schema",
  definition = [[
    table Root {
      research_value:uint (id:30);
      research_payload:[ubyte] (id:31);
      samples:[ResearchSample] (id:32);
    }
    struct ResearchSample { flag:ushort; weight:short; }
  ]],
}
```

- 只能在脚本加载阶段登记，所有脚本加载完成后一起验证，允许引用后登记的类型。
- `id` 必填且不得重复。声明中使用 `.fbs` 类型名，例如 `ushort`、`uint`、`[ubyte]`。
- 表按明确的 `(id:N)` 合并，只补充或替换列出的字段，不清除同表其他字段；目前 BTL 字段号范围为 0–511。
- 同一字段被不同声明覆盖时，后加载的声明生效。合并后字段名不能冲突，字段所引用的类型必须存在。
- 同名 `struct` 整体替换，因此必须写出完整成员布局。目前扩展结构体成员限标量；可声明普通表、表向量、结构体及结构体向量。
- 不能把已有 table 改成 struct，或反过来。扩展片段不接受 `include`、`root_type`、新 enum 或其他声明；已有 schema 中的枚举类型可以继续引用。
- 单个片段最多 100 万字符，连同基础 schema 的总文本最多 800 万字符。

基础 schema 保持不变，每份文档使用合并后的独立解释和指纹。热加载不会改变已经打开的文档。若新声明与当前文档不同，载荷接口要求重新打开；它不会清除原有未决数据诊断。

类型声明只负责物理解释，不会自动生成 `game` 属性或 XML 页面。新工具可以直接使用 `editor.data` 操作新字段，参数窗口仍由 `editor.tool` 生成。

结构体沿用现有核心的布局规则，本轮没有增加任意对齐或填充声明；必须核对实际字节布局。声明能力也不等于所有类型的编辑 API 都已开放，例如普通字符串字段的数字路径写入仍不支持。

## 2. 登记载荷编解码器

```lua
editor.format.codec {
  id = "my_research.packet",
  revision = "1",
  decode = function(bytes)
    assert(#bytes >= 8 and bytes[1] == 123, "不支持的载荷")
    return {value = editor.binary.read(bytes, 1, "u16"), raw = bytes}
  end,
  encode = function(packet)
    editor.binary.write(packet.raw, 1, "u16", packet.value)
    return packet.raw
  end,
}
```

`id`、`revision`、`decode` 和 `encode` 必填；同名编解码器重复登记会报错。`revision` 是研究版本字符串，定义该编解码器的 Lua 源文件同时记录内容指纹。

在工具或动作中使用：

```lua
local packet = editor.format.read("my_research.packet", "/31")
packet.value = 513
editor.format.write("my_research.packet", "/31", packet)
```

| 接口 | 约定 |
| --- | --- |
| `format.read(id,path)` | 读取已存在的普通 `u8` 向量，复制字节，调用 `decode`，返回脚本值 |
| `format.write(id,path,value)` | 调用 `encode`，完整验证输出字节数组后，在当前写事务中替换向量 |

`path` 使用数字路径，支持嵌套表和向量行。向量必须已存在；创建新载荷时可先用 `editor.data.ensure_vector(path,"u8")`。特殊编码标记非空的向量不能通过本接口访问，现有行为树仍使用 `editor.json`。

解码结果是脚本值，修改后需要明确调用 `write`。本轮采用按需解码、动作内写回；打开文件不会扫描执行所有解码器，保存文件不会执行 Lua 或隐式提交脚本变量。读取和未写回的修改都不改变文档；原字节向量仍是文档中的实际数据。

编解码函数只能处理传入的值，可使用基础 Lua 运算、位运算及 `editor.binary`。不能在其中访问文档、会话状态或调用其他编解码器。函数与调用它的动作共享指令、时间和取消预算。失败导致动作回滚；即使脚本用 `pcall` 捕获非法编码结果，也不会留下部分向量写入。

成功且确有修改时，工作文档记录载荷路径、编解码器 ID、研究版本和源文件指纹；这些记录随克隆、撤销、重做、外层事务回滚与工作 JSON 保存恢复。普通 BTL 不携带编辑器元数据。记录是使用来源，不是随集合行移动自动跟随的对象身份。

对已经记录的路径，使用不同编解码器、版本或源文件读取/写入会报版本不匹配。需要使用原脚本，或保存当前成果后，以新脚本重新打开 BTL。源文件指纹只覆盖定义该编解码器的文件，不自动追踪其他文件的函数依赖；依赖规则变化时也应更新 `revision`。

## 3. 二进制基础接口

字节数组是连续的 **1 起 Lua 数组**，每项为 0–255 整数；二进制偏移从 **0** 开始。载荷与新建缓冲区上限均为 200 万字节。

| 接口 | 说明 |
| --- | --- |
| `editor.binary.create(size)` | 创建指定长度、填零的字节数组 |
| `editor.binary.read(bytes,offset,type[,order])` | 读取一个标量，默认 `order="le"`，也支持 `"be"` |
| `editor.binary.write(bytes,offset,type,value[,order])` | 原地修改传入的 Lua 数组；不会自动扩容，也不直接写文档 |

支持 `u8/i8/u16/i16/u32/i32/u64/i64/f32/f64`。这里使用 Front 的短类型名，与 schema 声明使用的 `.fbs` 类型名不同。

- `u64/i64` 读取始终返回精确十进制字符串，写入也必须使用字符串，避免经过 Lua 数字丢失精度。
- 浮点读写只接受有限值；遇到 NaN、无穷大等特殊位模式，可保留原字节处理。
- 越界、非法字节序、小数写整数、超范围值均报错；验证失败不会部分写入缓冲区。
- 接口不包括通用压缩库、任意字符编码转换或完整文件偏移重定位。

```lua
local bytes = editor.binary.create(8)
editor.binary.write(bytes, 0, "u64", "18446744073709551615", "be")
assert(editor.binary.read(bytes, 0, "u64", "be") == "18446744073709551615")
```

## 4. 宿主集成与适用范围

编辑器已在异步打开、同步打开、JSON 打开及新建关卡入口使用脚本生成的解释上下文。其他 C# 调用方应在加载脚本后、读取文档前调用：

```csharp
var host = new ScriptHost();
host.Execute(extensionSource, "research.lua");
var context = host.CreateSchemaContext();
var result = BtlToFront.FromFile(path, context);
host.Load(result.Document);
```

这套接口适合“已确认 FlatBuffers 物理类型 + 独立字节载荷”的扩展。Lua 中的新字段声明能进入读取阶段，脚本编解码器也能通过通用入口操作载荷。未解析字段、任意未知偏移块、新的外层文件封装等仍需要进一步的格式研究与底层支持，不能仅凭脚本赋值就保证可重建。
