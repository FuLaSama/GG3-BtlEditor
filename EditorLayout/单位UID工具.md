# 按地块顺序分配单位 UID

打开关卡后，点击「脚本工具 → 按地块顺序分配单位 UID」。无需选择单位或填写参数；执行前会弹出 UID 引用风险提示，确认后才修改，取消不作修改。整次操作支持一步撤销、重做。原来的七项工具保留在 `examples/常用工具.lua` 中供参考，不再加载进默认菜单。

## 编号规则

- 地图内指 `0 <= 地块 ID < 地图宽 × 地图高`，与是否处于可游玩区域无关。
- 将地图内单位按地块 ID 从小到大编号为 `1、2、3……`，地块 ID 为 0 的单位也包括在内。
- 同一地块有多支单位时，按部队列表原来的先后顺序编号，保留所有单位；不会重排部队向量。
- 地图外单位优先保留不冲突的有效 UID；冲突、重复、为 0 或 65535 的编号，按原列表顺序分配到 N 之后的空位。先保留其他地图外单位的编号，避免连锁改号。
- 同步更新「下一个 UID」为全体单位最大 UID 加 1。因为此字段和 UID 都是 `ushort`，可用单位 UID 为 1～65534；超出容量时停止，保持文档不变。

## 引用处理

先记录全部旧 UID，再一次性生成新编号及引用映射，避免交换编号时发生二次替换。目前同步维护研究文件中已标注的这些位置：

| 引用 | 数字字段路径 |
| --- | --- |
| 部队 AI 目标 UID | `/6/0[i]/3/5` |
| 建筑招募单位的 AI 目标 UID（研究推定） | `/5/0[i]/3/2/5` |
| 部队组成员 UID | `/6/1[i]/1[j]` |
| 战略驻军成员 UID | `/6/3[i]/1[j]` |
| 按投放格分组的已有单位增援队列 | `/8/0[i]/1[j]/1` |
| 按势力分组的已有单位增援队列 | `/8/1[i]/1[j]/1` |

缺省引用不会被补建，0 按未指定目标保留；找不到对应旧单位的引用也保持原值。旧 UID 重复且被上述位置引用时，无法判定引用原本指向哪支单位，工具会停止并指出字段位置。没有引用歧义的重号可以正常修复。

这些引用依据当前研究维护，并不表示私有格式已经完全掌握。关卡 Lua、事件动作字节流、FlexBuffers 行为树的自定义参数、未研究字段中如另有 UID 语义，不会按数值盲目替换；使用这些内容的关卡需同步检查对应逻辑。

## 后续修改入口

菜单声明在 `scripts/tools/分配单位UID.lua`，调用 `game.units.assign_uids_by_cell()`；排序、地图外冲突及引用规则集中在 `scripts/common/单位UID.lua`。新增研究确认的 UID 引用，修改后者的 `references(visit)` 即可，不需要改 C# 或重新编译。修改后重新加载布局或重启编辑器生效。
